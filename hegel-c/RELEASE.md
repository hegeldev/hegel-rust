RELEASE_TYPE: patch

This release adds `hegel_pool_restore`, which puts back a variable that a consuming `hegel_pool_generate` removed from a pool, named by the id that draw returned, making it drawable again. A binding calls it when it throws away a consumed value unused, as a filter does with a rejected attempt, so the pool is left as if the draw had never happened. Any handle of the test-case family may put a variable back, whichever handle consumed it; a variable that is not a consumed variable of the pool fails with `HEGEL_E_INVALID_ARG`. Consumption is otherwise unchanged: libhegel never puts a variable back of its own accord, so a consumed variable stays consumed unless the binding restores it.
