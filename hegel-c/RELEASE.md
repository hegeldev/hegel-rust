RELEASE_TYPE: patch

This patch trims the fixed cost of every test case. After each case the engine no longer copies the case's choices and spans out of a test case nothing else can still see, hands the driver its data source without re-allocating it, and only indexes spans by label for span mutation when some label actually repeats. A test drawing a single value runs about 15% fewer instructions per test case, and shrinking runs 3–10% fewer.

This patch also stops the engine serializing each executed test case's choices twice. The nondeterminism detector and the execution cache both key on the same encoding of the case's values; the detector now writes that encoding once, into a buffer the run keeps, and the cache reads it from there. Integers that fit a machine word are encoded straight from their bytes instead of through an arbitrary-precision intermediate, and during generation — when the cache has no full entry to serve — span mutation no longer builds a lookup key that could not hit. The encoding itself is unchanged, so stored examples and reproduce blobs are unaffected. Tests drawing many values benefit most: a test drawing a hundred integers, or three derived structs, runs 28–36% fewer instructions per test case; single-draw tests 5–15% fewer; shrinking runs up to 14% fewer.

This patch also trims the shrinker's cost per attempt. Each attempt built the candidate's values once to look it up in the execution cache and then copied them again into the test case that replayed them; the replay now takes the first copy. The cache stores each entry's key once instead of twice, and comparing a candidate against the current best takes one pass over the two sequences instead of two. Shrinking a vector of booleans, integers or text runs 5–10% fewer instructions per attempt.

This patch also makes the nondeterminism detector's per-choice fingerprint cheaper to compute — two 64-bit hash lanes in place of one 128-bit multiply per byte — and stops it copying each choice's constraint just to compare it. Every executed test case pays this cost once per choice, so tests drawing many values and shrinking runs both gain about 2–3%.

This patch also removes one allocation from every test case: the family's pretty-printer document now lives inside the family's own allocation, and printer handles fetched from a test case reach it through the family. Tests drawing a single value run about 1% fewer instructions per test case.

This patch also hands each shrink attempt's candidate sequence to the test case that replays it instead of copying it, and slims the state the shrinker allocates per attempt so it fits the allocator's fast path again. Shrinking a vector of booleans runs about 8% fewer instructions per attempt; other shrinking runs about 1% fewer; generation about 0.3% fewer.

This patch also makes span mutation's preparation cheaper. After each valid test case the engine sorted every span to see whether any label repeated, then indexed the spans by label through a set per label and sorted each group again; it now groups them once, in plain lists, and a test case with few spans is checked without allocating at all. The proposals it makes are exactly the ones it made before. A recursive tree generator runs about 20% fewer instructions per test case, a large vector or a tuple of derived structs 5–8% fewer, and single-value tests about 2% fewer.

This patch also stops every integer draw allocating its own copy of the generator's bounds. Consecutive integer draws under the same bounds — a vector's elements, a state machine rule's key, a recursive tree's leaves — now share one copy, which the run's bookkeeping shares in turn instead of holding and later freeing a copy per draw. A hash map of integers or three derived structs runs about 9% fewer instructions per test case, a state machine 4–8% fewer, a recursive tree or a regex 6% fewer, and shrinking a struct 2% fewer.

This patch also sizes the test cases span mutation proposes before filling them, where the proposal that repeats a span had grown its sequence one doubling at a time. Tests drawing many values benefit: a vector of a hundred integers or three derived structs runs about 4% fewer instructions per test case, a large vector or a hash map about 3% fewer, and a state machine or a recursive tree about 1.5% fewer.

This patch also stops replays that may draw past their end — the probes span mutation makes after each valid test case, and the ones the shrinker uses to raise a value — from sampling a fresh set of the per-test-case generation weights before they start, when most of them never draw past the sequence they were given and so never use the weights. The weights are now sampled the moment a replay first needs its random draws, from the same random state as before, so every test case a seed produces is unchanged. Tests drawing many values run 9–16% fewer instructions per test case (a filtered or derived struct, a vector of integers, booleans or text, three derived structs), a hash map 9% fewer, and shrinking a recursive tree 18% fewer, a derived struct 14% fewer and a state machine 7% fewer.

This patch also replays each shrink attempt straight from the candidate the shrinker built. Every attempt used to copy the candidate's values out into a second sequence — a fresh copy of each integer, text and bytes value — encode that copy to look the attempt up in the execution cache, and then hand both sequences to the test case replaying them; the test case now takes the candidate itself and reads the values, and the constraints they were drawn under, from it. The attempts made and the values they replay are unchanged. Shrinking a vector of booleans runs about 9% fewer instructions per attempt, a vector of integers 6%, an integer or a text 4%, a derived struct, a recursive tree or a state machine 3%; generation runs about 1% fewer, the test case having grown smaller.

This patch also stops the engine copying the record of a cloned test case back into its parent once the test body has let go of the clone. Only tests that clone the test case — a state machine using a `Pool`, or a body calling `clone()` — pay for this; shrinking such a state machine runs about 2% fewer instructions per attempt, and generating it about 1% fewer.
