RELEASE_TYPE: minor

This patch fixes a run whose every test case is rejected ending as passed. A run that generates no valid test case now ends with `Unsatisfiable` (an error result over the C ABI, as for a test that draws no data and rejects its only input), however the health checks are configured: with `filter_too_much` suppressed, a test whose assumptions always fail used to spend its invalid budget and pass; with `test_cases_too_large` suppressed, a test whose every case overran the choice limit did the same.

It also removes the early stop on ten consecutive already-seen rejections, which guessed that the search space was exhausted. The guess was wrong often enough to matter: a test that accepts one of seven equally likely values had its run cut short after about twenty rejections roughly one time in twenty, passing with no valid input when `filter_too_much` was suppressed and failing that health check with a message about the whole search space being filtered when it was not. Generation now runs until the test-case budget or the invalid budget is spent; a small fully-filtered space reports `filter_too_much` at the usual fifty-rejection threshold.

This release stops generation once a small finite search space has been exhausted. The engine keeps a bounded record of the inputs tried while every draw has a small domain (a boolean, a forced value, or an integer over at most 4096 values), and ends the generation phase as soon as every possible input has concluded, where previously a test over a single `booleans()` draw ran its full `test_cases` budget. A test whose every input of such a space is rejected now fails as `Unsatisfiable`, saying every possible input was tried, rather than as a `FilterTooMuch` health check; verbose output reports the exhaustion. Tests that re-run identical inputs of a tiny space to surface nondeterminism now stop sooner, as a space with a wide draw (a float, a string, an unbounded integer) is not tracked.

Health check and `Unsatisfiable` messages no longer use Rust syntax for the setting that suppresses them: they name the check plainly ("suppress the FilterTooMuch health check with the suppress_health_check setting") and describe rejections as "rejected by assume() or a filter", since the engine does not know which did the rejecting. The `FailedHealthCheck:` and `Unsatisfiable` prefixes are unchanged.

Verbose output now announces every executed test case with `Running test case`, including the first, simplest input of a run and the replays of the reuse phase, which previously appeared under their phase heading with no announcement.

It adds `hegel_run_result_error_kind`, which reports why a run ended in `HEGEL_RUN_STATUS_ERROR` as a `hegel_run_error_kind_t` (a failed health check, a flaky or nondeterministic test under `error` strictness, an unsatisfiable test, a usage error, or an internal error) and, for a failed health check, which check as its `hegel_health_check_t` value. Bindings previously had to classify run errors by the wording of `hegel_run_result_error`, which a rewording could silently break; the message is unchanged and remains the diagnostic to attach.

```c
hegel_run_error_kind_t kind;
uint32_t check;
hegel_run_result_error_kind(ctx, result, &kind, &check);
if (kind == HEGEL_RUN_ERROR_HEALTH_CHECK && check == HEGEL_HC_FILTER_TOO_MUCH) { ... }
```

It makes targeting start much earlier in large runs. Previously the first hill-climbing pass over `hegel_target` scores began only after half of the run's test cases, so a failure that targeting leads to with `test_cases = 10000` was found around case 5,000. Runs of 1,000 test cases or more now start optimising after a short random warm-up and interleave targeting passes with random generation on a fair-share schedule, as Hypothesis does, so such failures are found within a few hundred cases; smaller runs keep their single pass halfway through.

It also reports the highest score observed for each `hegel_target` label. The run result carries them, read with the new `hegel_run_result_target_score_count` and `hegel_run_result_target_score`, and the `show_statistics` block ends with a `Highest target score` line (or a table for several labels), so a shrunk failing example can no longer hide how far the score was driven.

It fixes two reporting problems in runs that switched to nondeterministic handling. A failure observed once that never reproduced was dropped from the report as soon as another failure was confirmed; under `report_multiple_failures` it is now reported alongside the confirmed failures, caveated and without a reproduce blob (a single-failure report still prefers the confirmed failure). And the nondeterminism caveat is now per failure: a confirmed failure that reproduced at every replay is reported as a plain failure even when a different failure made the run nondeterministic, instead of being described as "nondeterministic failure, confirmed: failed 20 of 20 replays".

It fixes integer shrinking stopping short of the minimum on some values. A bounded integer whose failing values are a sparse set of multiples, such as the multiples of six, could stall at a value none of the shrinker's moves could leave: a search over `0..=100` for a positive multiple of six reported 78 rather than 6 from about one seed in twenty. The shrinker now also tries dividing the distance from `shrink_towards` by each of its prime factors, which steps straight from 78 to 6.

It fixes four problems with `hegel_string_generator_regex`. A pattern that the given alphabet cannot match (`abc` over `def`, `[^a]` over `a`, `\d` over letters, ...) and a pattern no string can match (`a^b`, `a\Zb`, `(?!foo)foo`, `abc(?<!abc)`, `(?!)`) are now reported as invalid arguments when the generator is built, naming the pattern and the alphabet or the reason, instead of every draw being rejected until the run fails the filter-too-much health check. Wildcards and character classes now shrink to the same character `text()` shrinks to (`.` and `..` shrink to `0` and `00`, `[a-z]` to `a`) rather than to U+0101. And under `re.IGNORECASE`, a negated class or `[^x]` whose excluded character has a multi-character case fold (`[^İ]+`: `İ` folds to `i` followed by U+0307) no longer emits the fold's components, so its output can never assemble the fold of the character it excludes.

It fixes `hegel_run_start_blob` replaying a reproduce blob against a test whose draws have changed. A replay that left the recorded choices (a draw whose kind or bounds no longer fit the recorded choice, or a draw past the end of the recording) used to be continued with fresh draws, so a failure the changed test happened to reach on that input was reported as the blob's failure. Blob replays are now exact: a replay stops at its first divergence, the run reports no failure (the blob did not reproduce), and one output line names the position, and stream, at which the test's draws left the recording. Database reuse and the report-time final replay keep their continuation budgets.

It makes pool consumption transactional. `hegel_pool_generate` with `consume=true` used to remove the drawn variable from the pool at draw time, so a value was lost whenever the draw that took it was thrown away: a consuming draw inside a filter's rejected attempt, inside a list element that was then rejected, or in a rule that went on to fail an assumption all left the pool short of a value no rule ever ran with. A variable now only leaves the pool for as long as the draw is kept: closing the span it was drawn in with `hegel_stop_span(discard=true)`, or reporting the rule step it was drawn in with `hegel_state_machine_rule_rejected`, puts it back, and it may then be drawn again. Bindings that drop their own value for a consumed id must keep it until the pool is freed, and can ask the pool's current size with the new `hegel_pool_len`.

It fixes `hegel_generate_uuid` repeating values within a run. Its two 64-bit halves were drawn with the boundary-biased integer distribution, so a few hundred UUIDs would usually contain duplicates and lists of UUIDs often held the same value twice. UUIDs are now uniformly random over the version's space, and still shrink towards small values.
