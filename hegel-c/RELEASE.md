RELEASE_TYPE: patch

This patch changes how the engine generates floats. Each test case now draws its own mixture of float value categories — range endpoints, values near zero and near `±1`, subnormals, integers and half-integers, the magnitudes whose sum or product overflows or underflows, NaN, `±∞`, `±MAX`, `±2^53`, `±0`, binade edges, non-dyadic values such as `0.1`, and a default draw — and every float in that case is drawn from that mixture, the way wide-range integers already were. A case that leans on one category correlates its draws, so `x + y` overflows or `x * y` underflows far more often than independent per-value boosts allow.

The default draw is a coin flip between a uniform value in the range and a log-uniform one, which gives every binade the range touches the same share all the way down to the smallest admitted magnitude. Bounded ranges such as `0.0..=10.0` therefore reach the deep-underflow scales where cancellation bugs live, rather than spending nearly every draw within a factor of a thousand of the top bound. Draws for `f32` are steered toward `f32`'s own landmarks (`f32::MAX`, `2^24`, its subnormals) instead of `f64`'s.

Only fresh generation changes: the recorded choice sequence, replay, shrinking and stored failures are untouched.

It also improves two shrinker passes. Duplicated values are now shrunk before spans are replaced by their simplest values, and each duplicated group is finished before the next is started, so a size drawn twice (the rows and columns of a square matrix) is lowered while the values it governs still vary; previously the values were zeroed first, after which no smaller size could stay interesting and the shrinker stopped at a larger square. When bumping a choice shortens the test's path, the shrinker now also tries keeping the later choices less the first few the new path no longer draws, so a `one_of` whose pair branch `(false, true)` fails a test shrinks to its lone-`true` branch instead of staying on the pair.
