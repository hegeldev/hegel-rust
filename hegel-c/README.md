# hegeltest-c

C-ABI bindings for [hegel](https://hegel.dev)'s native property-based
testing engine. The build artefacts are shared and static libraries plus a
checked-in C header at
`include/hegel.h` (generated by `cbindgen` from `src/lib.rs`). The engine's
handling of nondeterministic tests is described in
[`docs/nondeterminism.md`](docs/nondeterminism.md).

**This crate is published mostly to reserve the name on crates.io.**
If you want to *use* libhegel from a non-Rust language, you almost
certainly want the prebuilt libraries + header from a GitHub release
rather than building this crate yourself:

> <https://github.com/hegeldev/hegel-rust/releases>

libhegel releases are tagged `libhegel-v<version>` and titled
`libhegel v<version>`; the repository's plain `v<version>` tags are the
`hegeltest` crate's releases, which carry no binaries. Each libhegel release
publishes shared and static
`libhegel-<goos>-<goarch>.<ext>` libraries, `hegel.h`, and matching
`.sha256` sidecars for `linux/amd64`, `linux/arm64`, `darwin/arm64`,
`windows/amd64`, and `windows/arm64`. Intel macOS (`darwin/amd64`) is not
published; build the crate yourself if you need it. Releases also include the
`wasm32-unknown-unknown` WebAssembly module and static archive.

## WebAssembly build

The raw C ABI can also be built for `wasm32-unknown-unknown`:

```bash
rustup toolchain install "$(cat hegel-c/wasm-toolchain)" --profile minimal --target wasm32-unknown-unknown
just c-build-wasm
```

`hegel-c/wasm-toolchain` pins Rust 1.97.1 for local builds, CI, and release
artifacts. Wasm consumers must use its C-compatible aggregate ABI: a
by-value `hegel_string_t` input is passed as an address of an eight-byte
`{data, len}` descriptor in linear memory; a returned string uses a hidden
output address before the explicit parameters. Rust 1.86 used a different
aggregate ABI and is unsupported for Wasm builds. The native MSRV remains
1.86. Rust callers linking the Wasm static archive must also use the pinned
toolchain.

`just c-build-wasm` also builds the static archive with the `wasm-static`
feature. The resulting module uses `hegel_host.entropy_fill` and
`hegel_host.monotonic_nanos` for platform services. The static archive uses the
stable C symbols `hegel_host_entropy_fill` and `hegel_host_monotonic_nanos` for
the same hooks. Filesystem persistence and concurrent state machines are
unavailable in this single-threaded build; a browser or other host binding
supplies the imports and Wasm memory handling.
