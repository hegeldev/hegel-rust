RELEASE_TYPE: patch

This release adds `Generator::reject`, a method with a default that does nothing, which a combinator calls to hand back a value it drew from the generator and is discarding unused, so the generator can undo any side effect of the draw. `filter` now hands each rejected attempt back this way, and `Pool::values_consumed` / `ConcurrentPool::values_consumed` put a handed-back value in the pool again, so filtering a consuming pool draw consumes only the value the test receives rather than losing every rejected attempt's value too. Nothing else restores a consumed value: one that reaches a rule which then fails an `assume`, or one drawn through another combinator such as `map` or `vecs`, stays consumed even if a filter around that combinator rejects the result.
