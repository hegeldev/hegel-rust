RELEASE_TYPE: minor

This patch fixes a test whose every input is rejected by `assume()` or `reject()` passing when `HealthCheck::FilterTooMuch` is suppressed. Such a run now fails with `Unsatisfiable`, as a test that rejects its input without drawing anything already did, since no valid input was ever generated; the same applies to a test whose every input overruns the choice limit with `HealthCheck::TestCasesTooLarge` suppressed.

It also fixes a test that accepts only a rare input — say one of seven equally likely values — sometimes stopping after about twenty rejections, passing vacuously under suppression or failing `FilterTooMuch` with a message claiming the whole search space had been filtered. Generation now continues until the test-case budget or the invalid budget is spent.

It improves `tc.target()`: targeting now steers generation from early in a large run instead of only from halfway through its budget, and a failing run's report ends with Hypothesis's `Highest target score: N  (label="...")` line (a table for several labels) showing the highest score observed for each target label, so the shrunk example cannot hide how far targeting drove the score. The line is omitted under `Verbosity::Quiet`.

It improves the failure report for a nondeterministic failure that was observed once and never reproduced: when it is reported alongside other failures, its block now shows the panic site and message instead of only the caveat note.

It changes what `#[hegel::reproduce_failure]` reports when the test no longer draws as it did when the blob was recorded (a different generator, or an extra draw before the failing one): the replay now stops at that draw and panics with the usual did-not-reproduce message, preceded by the engine's line naming the divergence, instead of continuing with fresh draws and possibly reporting an unrelated failure as if the blob had reproduced it. A blob that replays exactly and fails still re-raises the test's own panic.

This release fixes `Pool::values_consumed` and `ConcurrentPool::values_consumed` removing values the test never used: a consuming draw rejected by `filter`, or made by a rule that then failed an `assume`, took the value out of the pool anyway. A value now only leaves the pool when the draw that took it is kept. Because a discarded draw puts its value back, the pool now keeps every value it is given and consuming draws yield a clone, so drawing from `values_consumed()` requires `T: Clone` (wrap values in `Rc` or `Arc` if cloning is expensive); `Pool::values_consumed` now takes `&self`, and `len`/`is_empty` on both pool types report the engine's view of the pool.

It fixes collections of distinct elements drawn from `sampled_from` failing `FilterTooMuch` when they needed most or all of the values: `gs::hashsets(gs::sampled_from(0..50)).min_size(50)` (and `btree_sets`, `vecs(..).unique(true)`, and the keys of `hashmaps` and `btree_maps`) drew each element independently and rejected duplicates, so a full set was never reached. Such collections now draw from the list without replacement, never exceed its length, and shrink to its first elements. A minimum size the list cannot satisfy is reported as an invalid argument (`Cannot generate 5 unique elements from a list of length 3`) instead of a health-check failure. This adds the hidden `Generator::sample_space` and `PrintableGenerator::sample_printer` hooks that `sampled_from` implements.
