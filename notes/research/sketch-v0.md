# Design sketch v0 (superseded)

> The first mechanism sketch, 2026-09-02, preserved because the `critique-*.md` reviews refer to
> its numbered areas. Superseded by `../design.md`, which records what changed and why.

Constraints set going in:

- Target: handle tests that fail >= 10% of the time when run; detect nondeterminism, don't just have it declared.
- No notice by default: new setting `nondeterminism_strictness = Quiet|Warn|Error`, default Quiet. Error preserves today's `RunError::Flaky` / `RunError::NonDeterministic` aborts; Quiet silently flips the run into ND mode and handles it.
- Shrinking must not lower failure probability by default; if probability rises during shrinking, keep it high; ideally boost probability before shrinking; if shrinking reaches a deterministically-failing region, stay there. Beware small-sample overconfidence.
- Prefer running each shrink pass multiple times with a cheap (single-run) predicate over running every candidate N times.
- Per-origin failure identity stays.
- ND-node representation: a branch point in the recorded test case with tree-shaped per-value suffixes (may differ per value, possibly per kind).
- Restore the data tree for ND runs if feasible (low priority; disabling is acceptable).
- Persist per-test ND status so later runs start in ND mode. Unify reporting: the NondetStash capture-at-discovery design is a temporary bandaid, not canonical.
- Top workloads: concurrent stateful, then plain clone-based concurrency; external randomness/timing should fall out automatically. Ignore the parallel-tests branch and Antithesis.

Mechanism sketch:

1. **Mode lifecycle**: run flips deterministic -> ND when (a) declared (`max_concurrency > 1` machine) or (b) detected: any current abort site (data-tree kind mismatch on reuse/probe/generation/verify; verify status/origin flake; final blob replay flake; DB reuse divergence) becomes a flip site under Quiet/Warn. ND status persisted in the DB under a sub-key; cleared when a full ND-mode run observes zero divergence. With unified reporting (below), cases no longer need to be stamped nondeterministic before they start, so the current sacrifice-the-flipping-case trick can go away.
2. **Interestingness**: for ND runs, confirming a failure = replay up to N (10) times, stop at first failure. If nothing reproduces, still fail the run, reporting the originally-observed failure with a caveat naming both hypotheses (rare failure vs. environment modification).
3. **ND nodes**: during replay, when a recorded value/kind no longer fits the requested draw, instead of silent punning, widen that position into an ND node holding multiple branches, each branch = (head value, tree-shaped suffix of nodes+spans, like Clone's RealizedStream nesting). Replay at an ND node picks the first branch whose head satisfies the current constraint (failing-timeline-first ordering), else generates fresh randomly with a capped continuation budget; new realized timelines can be folded back in as new branches (branch count capped). Outcome-ND (same realized sequence, different verdict) needs no ND node — handled purely by the multi-run predicate. Storage: new choice-sequence element (DB type tag + new blob prefix byte); sort key extended (failing branch's key first, then branch count/size).
4. **Data tree**: kind-mismatch-at-record widens the tree node into an ND tree node instead of erroring; conclusions become outcome distributions ({status, origin} -> count) instead of single cached verdicts; ND nodes treated as never-exhausted (like clone subtrees); novel-prefix generation restored for ND runs. Candidate-level failure-rate stats may need a separate store keyed by proposed candidate, since the tree is keyed by realized paths.
5. **Shrinking**: single-run predicate per candidate; run passes repeatedly (loop-until-K-dry fixpoint instead of one-clean-iteration); checkpoint validation — at pass boundaries re-validate the incumbent with a k-run sample and roll back to the last checkpoint if failure rate collapsed. Ratchet classes for the incumbent: deterministic (never seen passing) > high-p > low-p; accepting a candidate against a stronger-class incumbent demands consecutive failures (sequential test, cost scales with incumbent class). Probability-boost phase before shrinking, reusing targeting/Optimiser machinery with score = observed failure rate (or -attempts-to-first-failure). Cross-timeline passes: at an ND node, graft the failing branch's suffix values onto candidates that landed in passing branches (donor-splicing like span mutation / pass_to_descendant).
6. **Reporting**: ND failures carry blobs (new format). Final replay = run blob up to N, report the first failing execution rendered fresh; if none fails, caveated report from a discovery-time capture (per-origin, replacing the single-slot NondetStash); report_multiple_failures works under ND. DB reuse replays each stored entry up to a small N before deleting.

Main things the adversarial review killed or changed (details in the critiques and `../design.md`): the merged ND-node artifact (no stable trunk; replaced by the timeline pool), misfit-anchored widening (dominant divergence class is invisible to it; structural signals needed), DB-reuse divergence as a flip site (usually a code change), persisted ND status and rate estimates (only the representation persists), "no stamping needed" (capture decisions happen before the body runs; replaced by capture-at-confirmation), raw-streak ratchet classes (confidence bounds over an evidence ledger), rollback against the previous checkpoint (monotone anchor), and unguarded single-run accepts (the accept gauntlet).
