# Code map: database-blobs

> Research notes compiled 2026-09-02 at commit a0185a65 (branch base, == main at the time).
> References are `path:line` at that commit. Part of the nondeterminism design notes; see `../design.md`.

SUMMARY: The failure database is a filesystem-backed multi-value key/value store (one directory per FNV-hashed key, one file per FNV-hashed value) holding serialized choice sequences under a primary key (the test's `module::test_name`) plus a `<key>.secondary` sub-corpus of displaced/older counterexamples. Reproduce blobs are base64(prefix byte + optionally-zlib'd serialize_choices bytes) with no version field — explicitly documented as only valid within one Hegel version. Replay (Phase::Reuse) deletes entries that deserialize but no longer fail, deletes undecodable entries, skips shrinking when a primary entry replays byte-aligned, and the whole persistence machinery (incremental saves, end-of-run reconciliation, reuse, blob emission) is skipped when the run's sticky `nondeterministic` flag is set. Nothing else (targeting, pools, statistics, data tree) is persisted across runs.

## Database trait and directory store
TestCaseDatabase trait: fetch/save/delete/move_value over multi-value keys; failures must be silent no-ops. DirectoryTestCaseDatabase stores each key as directory <db_root>/<fnv_hex("native:"+key)> and each value as file <dir>/<fnv_hex(value)>, written via atomic temp-file+rename (temp_path uses pid+AtomicU64 counter). A bookkeeping key METAKEYS_NAME=b".hegel-keys" records every live key; delete removes the dir when empty and unregisters the key. FNV-1a 64 is used for all on-disk names (collision-avoidance only).

## Database keys and configuration
Primary key = the frontend-supplied database_key string; #[hegel::test] sets it to format!("{}::{}", module_path!(), test_name) via Hegel::__database_key. Secondary corpus key = sub_key(primary, b"secondary") i.e. primary + "." + "secondary" (only sub-corpus that exists; mirrors ConjectureRunner.sub_key). Engine default path is ".hegel/examples" when Database::Unset; Database::Disabled → no db. Frontend defaults: Database::Unset normally, Database::Disabled in CI (auto-detected), overridable by HEGEL_DATABASE env (value "disabled" turns it off). Derandomize (default-on in CI) seeds the engine RNG from fnv1a(database_key).

## Choice-sequence serialization format (database values)
serialize_choices: 4-byte LE u32 count, then per choice a 1-byte type tag (0=Integer, 1=Boolean, 2=Float, 3=Bytes, 4=String, 5=Clone). Integers always written as sub-tag 10 (BigInt: LE length + two's-complement LE bytes); legacy per-width sub-tags 0–9 still accepted on read. Float = raw f64 bits LE (NaN payloads / -0.0 round-trip). String = codepoint count + 4 bytes per codepoint. Clone = the cloned stream's child values recursively in the same layout — only values are persisted; spans/kinds are recreated on replay. deserialize_choices returns None on any truncation/unknown tag/clone nesting beyond MAX_CLONE_DEPTH. No version byte anywhere in the value encoding.
refs: hegel-c/src/native/database.rs:197-268, hegel-c/src/native/database.rs:272-317, hegel-c/src/native/database.rs:319-415

## Reproduce blob encoding
encode_failure = base64(prefix_byte ++ payload) using padded standard-alphabet RFC 4648 base64 (own impl in base64.rs); prefix 0=raw serialize_choices bytes, 1=zlib(level 6, miniz_oxide) — whichever is shorter wins. decode_failure returns None on any malformation. Versioning: none in-band; module doc states the encoding "is only guaranteed to reproduce a failure within a specific version of Hegel". Blobs are computed in explore() from the final shrunk nodes per origin, and set to None when the run is nondeterministic.
refs: hegel-c/src/native/blob.rs:39-79, hegel-c/src/native/base64.rs:4-29, hegel-c/src/native/test_runner.rs:634-649

## When entries are written: incremental Persister
Persister::record runs on every Interesting result (Engine::record_run, gated on !self.nondeterministic): first sighting of an origin, or a sort_key improvement over the last save, writes the serialized choices to the primary key and move_value()s the previously-saved bytes for that origin to the secondary key. Incremental persistence is explicitly so a failure survives Ctrl-C/SIGTERM mid-shrink. In-memory `interesting: HashMap<origin, Vec<ChoiceNode>>` tracks the shortlex-best per origin in parallel (update_interesting).
refs: hegel-c/src/native/test_runner.rs:881-937, hegel-c/src/native/test_runner.rs:1113-1124, hegel-c/src/native/test_runner.rs:864-879

## End-of-run database reconciliation
After shrinking (and skipped entirely when self.nondeterministic), explore() computes the final serialized entry set from `interesting`, fetches the primary key, move_value()s any primary entry not in the new set to the secondary key, then saves all new entries to the primary key. So the primary corpus always ends as exactly the final shrunk counterexamples; everything displaced lives under `<key>.secondary`.
refs: hegel-c/src/native/test_runner.rs:588-608

## Phase::Reuse replay semantics
Reuse fetches primary entries, sorts shortlex, and if below desired_size (max(2, ceil(test_cases * 0.1)) with Generate enabled, else *1.0) tops up with a random sample of secondary entries (also shortlex-sorted, primaries first). Each entry: (a) fails to deserialize → deleted from BOTH primary and secondary keys and skipped; (b) replays and is still Interesting → kept (and recorded by Persister as usual); breaks early unless report_multiple_failures; (c) replays as anything else (passes/invalid/overrun now) → silently deleted from both keys — no retry, no report to the user. Secondary replays stop after the first interesting-in-primary is found. Replay uses NativeTestCase::for_probe (choices + rng continuation budget BUFFER_SIZE).
refs: hegel-c/src/native/test_runner.rs:198-283, hegel-c/src/native/test_runner.rs:236-241, hegel-c/src/native/test_runner.rs:267-272

## replay_aligned: shrink skipped on faithful DB replay
replay_aligned starts true iff primary entries existed; it stays true only if a primary entry replayed Interesting with node-for-node identical values to the stored choices (checked value_ref against stored). Any mismatch, a bug found only via secondary, an empty interesting set, or nondeterminism clears it. When still true, the whole shrink phase is skipped ("Skipping shrink: reused aligned database replay") — the stored example IS the report. Reuse-found bugs also suppress the generation phase entirely (found_in_reuse gates all generate loops).

## Secondary corpus consumed at shrink start
At the start of the shrink phase, secondary entries shortlex ≤ the largest current primary candidate are replayed via NativeTestCase::for_choices (bare replay, no rng extension) — they may improve `interesting` through record_run — and each is deleted from the secondary key afterward regardless of outcome. Then each origin is verified by re-running its exact choices; a verify that is not Interesting with the same origin returns RunError::Flaky(flaky_diagnostic()).
refs: hegel-c/src/native/test_runner.rs:484-515, hegel-c/src/native/test_runner.rs:533-545, hegel-c/src/native/test_runner.rs:762-769

## Determinism checks during replay
Every executed case is recorded into the lossless choice tree (record_tree_full) unless nondeterministic; a recording that contradicts an earlier run returns a mismatch string which the reuse loop, initial-simplest run, generation loop, and shrink-verify all convert to RunError::NonDeterministic — aborting the run with an error rather than a verdict. Separately, the frontend's final blob replay that no longer fails panics with FLAKY_DIAGNOSTIC (run_lifecycle.rs:622-624); an explicit #[reproduce_failure] blob that decodes but passes panics 'blob no longer reproduces a failure ... may have been fixed, or the blob is stale' (run_lifecycle.rs:729-735).

## Frontend #[reproduce_failure] plumbing
#[hegel::test] extracts stacked #[hegel::reproduce_failure(blob)] attrs (extract_reproduce_failure in hegel-macros/src/common.rs:382) and lowers the FIRST to Hegel::reproduce_failure(blob) (first-wins; rest are bookkeeping). The standalone reproduce_failure proc-macro only fires to emit ordering/usage compile errors — in correct usage hegel::test consumes the attribute first. Hegel::run with a blob set calls drive_blob_replay, which builds a CTestCase via hegel_test_case_from_blob (engine side: decode_failure → NativeTestCase::for_choices, no rng extension), runs it once as final, re-raises the panic on reproduction, and panics 'stale blob' otherwise. Note src/explicit_test_case.rs is unrelated (explicit values, not blobs).

## How blobs surface in the failure report
engine Failure {origin, reproduce_blob: Option<String>} (blob None for nondeterministic runs and Mode::SingleTestCase); TestRunResult {failures, nondeterministic}. The frontend reads blobs off the finished run via ffi::RunResult::failure → hegel_failure_reproduction_blob (frontend ffi::Failure holds only reproduce_blob). drive() replays each blob through CTestCase::from_blob as the FINAL replay that produces the diagnostic and re-raised panic; reproducer_line prints '#[hegel::reproduce_failure("{blob}")]' only when Settings::print_blob (default false) AND a blob exists. FAILED_NONDETERMINISTIC runs instead print the NondetStash captured at discovery time (buffered lines + diagnostic + payload) since there is no blob and no final replay.

## Nondeterministic-mode interactions with persistence
Engine.nondeterministic is a sticky run flag flipped by the first case creating a state machine with max_concurrency > 1. While set: record_run skips tree recording (so no mismatch check), Persister.record is skipped (test_runner.rs:1120-1122), end-of-run reconciliation is skipped (line 588 guard), shrink phase is skipped (line 473), reuse breaks out (lines 273-276), and blobs are None (lines 638-643). concurrent_machine_notice explains failures are reported 'without shrinking, replay, database persistence, or a reproduce blob'. Reuse itself can flip the flag mid-phase (a stored entry that creates a concurrent machine when the run isn't yet nondeterministic is rejected — set_reject_concurrent_machine(!nondeterministic)).
refs: hegel-c/src/native/test_runner.rs:988-998, hegel-c/src/native/test_runner.rs:1052-1073, hegel-c/src/native/test_runner.rs:1084-1096, hegel-c/src/native/test_runner.rs:1119-1122, hegel-c/src/native/test_runner.rs:588, hegel-c/src/native/test_runner.rs:473, hegel-c/src/native/test_runner.rs:273-276, hegel-c/src/native/test_runner.rs:777-781

## Nothing else is persisted across runs
TargetingState (best score + choices per label) and TargetingSchedule are purely in-memory per-run; RunStatistics (events) is in-memory and only fed during the generation phase; pools (NativeVariables) and the data tree / novel-prefix state are per-run in-memory. grep for database/save/fetch in targeting.rs, statistics.rs, events.rs finds nothing. The only cross-run state is the two database corpora (primary + ".secondary") plus the ".hegel-keys" metakey — all containing serialize_choices values whose usefulness assumes replaying the same choices reproduces the same outcome.
refs: hegel-c/src/native/targeting.rs:22-59, hegel-c/src/native/test_runner.rs:970-978, hegel-c/src/native/test_runner.rs:1102-1108, hegel-c/src/native/database.rs:40

RELEVANCE: Every persistence feature is built on the assumption that a stored choice sequence deterministically reproduces its outcome: Reuse silently DELETES any entry that doesn't replay Interesting (test_runner.rs:267-272), so a probabilistically-failing test would have its counterexample corpus erased on the first lucky replay; replay_aligned additionally requires node-for-node value identity to skip shrinking, and any divergence during recorded replay hard-fails the run as RunError::NonDeterministic via the choice tree, while a same-choices outcome flip fails as RunError::Flaky. Reproduce blobs encode only choice values (no spans, no outcome, no version, no probability metadata), and the frontend's final report is produced by replaying the blob and REQUIRING it to fail again (run_lifecycle.rs:622-624 panics FLAKY otherwise) — so blobs are unusable as-is for tests that fail only sometimes. The existing concurrent-stateful escape hatch is total abstinence: the sticky Engine.nondeterministic flag disables saving, reuse, reconciliation, shrinking, and blob emission wholesale, and the frontend compensates with the discovery-time NondetStash. Useful extension points that already exist: the database is a generic multi-value store with a sub-corpus convention (sub_key), Persister saves incrementally and per-origin, Failure.reproduce_blob is already Option, TestRunResult already carries a nondeterministic bit across the C ABI (HEGEL_RUN_STATUS_FAILED_NONDETERMINISTIC), and blob decoding already treats any unknown prefix byte as undecodable, giving a natural place to version a new blob format.
