# Code map: shrinker

> Research notes compiled 2026-09-02 at commit a0185a65 (branch base, == main at the time).
> References are `path:line` at that commit. Part of the nondeterminism design notes; see `../design.md`.

SUMMARY: The shrinker (hegel-c/src/native/shrinker/) is a per-origin, choice-sequence minimizer driven to fixpoint over ~33 named passes. Every candidate is judged through a single chokepoint (Shrinker::run_test_fn -> ShrinkProbe::run -> EngineShrinkProbe -> Engine::cached_test_function), where "interesting" means status==Interesting AND origin string equals the origin being shrunk. There is no shrinker-local result cache; deduplication of repeated candidates is done entirely by the engine's lossless choice tree (data_tree::simulate_full), which stores exactly one outcome per choice path and treats a kind-change at a recorded position as fatal nondeterminism. Misalignment (a mutated sequence causing the test to draw differently) is handled by value punning at draw time, by always adopting the run's realized nodes rather than the proposed candidate, and by per-pass NodeGone recovery; several passes additionally do observation runs whose realized nodes/spans feed deliberate misalignment-repair splices.

## Entry: how the shrinker receives the interesting test case
explore()'s shrink phase runs only when `!self.nondeterministic` and shrink_phase is enabled. Per pending origin (sorted, one full shrink each) it first RE-RUNS the stored interesting nodes as a verification replay via Engine::test_function; a choice-tree mismatch returns RunError::NonDeterministic and a replay that is not Interesting with the same origin returns RunError::Flaky, aborting the run. Then it builds EngineShrinkProbe{engine, target_origin, ...}, constructs Shrinker::with_probe(probe, verify.nodes, initial_spans), sets shrinker.deadline (now + MAX_SHRINKING_SECONDS=300s, core/mod.rs:84), runs initial_coarse_reduction() once, then shrink(); the result replaces self.interesting[origin].

## Shrinker state and budgets
Shrinker holds current_nodes (Vec<ChoiceNode>, the shrink target), current_spans (Spans from the run that produced current_nodes), improvements (capped by max_improvements=MAX_SHRINKS=500), calls / calls_at_last_shrink / max_stall (stall guard: after >=1 improvement, consider/probe silently return false once calls-calls_at_last_shrink >= max_stall; max_stall grows 2x on each accepted shrink), last_checkpoint_nodes + all_changed_nodes (change tracking diffed on shape-preserving improvements, cleared when shape changes; consumed by lower_common_node_offset), deadline/timed_out (wall clock; run_test_fn returns ShrinkHalt::Stop past deadline).

## Pass structure and main loop / fixpoint detection
shrink_inner builds a Vec<ShrinkPass> of ~33 named passes (remove_discarded, span passes, node_program_5..1, delete_chunks, zero_choices, integer/float/string/bytes value passes, shrink_clone_streams, and mutate_and_shrink marked .stochastic()). fixate_shrink_passes loops `while any_ran`: each outer iteration resets the stall window (calls_at_last_shrink = calls), steps every pass; a deterministic pass is re-stepped only while each step improves (max_failures=1), a stochastic pass gets STOCHASTIC_MAX_FAILURES=6 consecutive non-improving steps; progress detection is `self.improvements > epoch_before_iter`. Between iterations passes are re-sorted by reorder key (deleted nodes:-1, improved:0, useless:1). Fixpoint = one full outer iteration with zero improvements. remove_discarded is also interleaved between passes while it succeeds.
refs: hegel-c/src/native/shrinker/mod.rs:559-695, hegel-c/src/native/shrinker/scheduling.rs:112-189, hegel-c/src/native/shrinker/scheduling.rs:55-79

## Interestingness predicate: execution path and origin matching
ShrinkProbe trait (mod.rs:68-79) returns (is_interesting, actual_nodes, actual_spans). The engine impl is EngineShrinkProbe::run: ShrinkRun::Full(nodes) -> engine.cached_test_function(values_of(nodes), Some(nodes), extend=0); ShrinkRun::Probe{prefix,max_size} -> cached_test_function(prefix, None, extend=max_size-prefix.len()) with random continuation from a spawned engine RNG. `matches = run.status == Status::Interesting && run.origin.as_deref() == Some(target_origin)` — origin is the panic file:line:col string captured by run_lifecycle::run_test_case (RunResult doc, test_runner.rs:48-57). All shrinker execution funnels through Shrinker::run_test_fn (mod.rs:358-366), the single choke point used by consider, probe, replace, and passes' direct observation runs — this (or EngineShrinkProbe/cached_test_function on the engine side) is where a 'run it up to N times' hook would sit, but it must contend with the tree cache below.

## consider(): the acceptance predicate
Shrinker::consider(nodes): (1) equal sort_key to current -> Ok(true) WITHOUT executing; (2) shortlex-worse candidate -> Ok(false) without executing; (3) same-length candidate changing a was_forced node's value -> false without executing; (4) improvement/stall caps; then one execution via run_test_fn(ShrinkRun::Full). Accepts iff is_interesting && sort_key(actual_nodes) < sort_key(current_nodes); accept_improvement stores the ACTUAL realized nodes+spans (not the candidate) and pushes the displaced value sequence onto self.downgraded (later persisted as secondary DB entries by explore). probe() is the same accept rule for random-continuation runs.
refs: hegel-c/src/native/shrinker/mod.rs:294-348, hegel-c/src/native/shrinker/mod.rs:372-393, hegel-c/src/native/shrinker/mod.rs:398-415, hegel-c/src/native/test_runner.rs:484-514

## Caching: the choice tree is the only memoization, keyed by choice path
The Shrinker has no negative-result cache (explicitly noted in tests: 'repeated candidates are deduped by the engine's data cache and choice tree behind the test closure'). Engine::cached_test_function first calls data_tree::simulate_full(tree_root, choices, nodes): the lossless trie stores per-path kind, children keyed by ChoiceValueKey, span events, and a Conclusion{status, origin, target_observations}; a recorded path of ANY status is served without running the body (predicted overrun served as EarlyStop only when extend==0). On a miss it executes via test_function, which records the run into the tree (record_run -> record_tree_full), so a later identical proposal is served from the tree. Every shrinker execution therefore both reads and writes this cache.
refs: hegel-c/tests/embedded/native/shrinker_cache_tests.rs:1-8, hegel-c/src/native/test_runner.rs:1174-1224, hegel-c/src/native/data_tree.rs:597-671, hegel-c/src/native/test_runner.rs:1083-1127, hegel-c/src/native/data_tree.rs:249-333

## What breaks in the cache if the same sequence can yield different outcomes
(a) simulate_full permanently serves the FIRST recorded outcome for a path — a probabilistically-failing candidate is frozen at whatever its first execution returned, so re-running is impossible without bypassing the tree. (b) record_tree_full's only nondeterminism detection is a choice-KIND change at a recorded position (returns the 'Your data generation is non-deterministic' message, data_tree.rs:268-276); a changed status/origin at the same path is silently overwritten in leaf.conclusion (data_tree.rs:307-315). (c) During shrinking the mismatch from test_function is DISCARDED: cached_test_function does `let (run, _mismatch) = self.test_function(ntc).await?` (test_runner.rs:1222); mismatch only aborts the run at the pre-shrink verification replay (test_runner.rs:537-539). (d) consider's no-execute fast paths (equal-sort-key true, worse-key false) assume outcome is a pure function of the sequence.

## Alignment assumption 1: punning at draw time
A bare replay (NativeTestCase::for_choices) sets max_size = choices.len() (floored in for_choices_and_template); a draw past the prefix hits pre_choice -> conclude(Status::EarlyStop) + EngineError::Overrun (state.rs:2428-2440), so a shortened/diverged candidate that draws more becomes EarlyStop (never Interesting -> rejected). A prefix value that no longer fits the draw's constraint is PUNNED in resolve_choice: to the draw's simplest() when the stale value equalled its original kind's simplest (using prefix_nodes), else to kind.unit() (state.rs:2442-2492). simulate_full mirrors the same punning during tree walks (data_tree.rs:642-656). Probe runs (for_probe, state.rs:1735-1741) instead extend with random draws up to max_size.

## Alignment assumption 2: shrinker-side recovery from misalignment
consider stores actual realized nodes, so shortening/punning is absorbed by adoption (mod.rs:294-311 doc). PassExit::NodeGone (mod.rs:130-155): per-node passes re-read the node's typed value each step (.ok_or(PassExit::NodeGone)) and abandon a node whose kind was punned or index deleted mid-pass; replace() rejects out-of-range indices, forced nodes, and values whose variant no longer fits the kind (mod.rs:469-484). Deliberate misalignment repair: try_replace_with_deletion runs an observation replay, computes deficit = expected_len - actual_nodes.len(), and tries deleting deficit-sized windows (deletion.rs:99-136); minimize_individual_choices compares candidate vs actual nodes per-position to truncate strings/bytes to realized lengths and splices out realized spans (deletion.rs:193-249); try_trivial_spans re-splices the realized span content from a failed attempt's actual_nodes/actual_spans (spans.rs:121-139); coarse reduce_each_alternative uses a zeroing observation run to detect shape change (coarse.rs:51-71); mutate_and_shrink's replay_observing_divergence detects branch switches by comparing realized kinds past position i, then invests DIVERGENT_RANDOM_ATTEMPTS=32 random-continuation probes to repair the suffix (mutation.rs:19-30,141-174).

## Span access in passes and data copying between test cases
Span-aware passes read Shrinker::current_spans (updated on every accepted improvement): remove_discarded deletes all non-overlapping discarded span ranges in one candidate (spans.rs:58-84); try_trivial_spans replaces span node ranges with kind-simplest values (spans.rs:95-143); pass_to_descendant splices a same-label strictly-contained shorter descendant span's nodes over its ancestor — the recursive-collapse pass (spans.rs:155-200); reorder_spans permutes same-label same-parent sibling span ranges via shrink_ordering/PermutationJudge keyed by NodesSortKey of each slice (spans.rs:214-283, ordering.rs:41-183). All of these copy node slices between positions of a snapshot of current_nodes and re-run via consider. shrink_clone_streams runs a full RECURSIVE nested Shrinker per clone node: NestedCloneProbe splices each nested candidate into the parent template (splice_child) and reads the realized child stream back out of the run's clone node at position i, returning (false, empty) when position i is no longer a clone node (clones.rs:25-127).

## Duplicated-span mutation machinery (generation phase, not a shrink pass)
Engine::try_span_mutation runs during generation (gated on !nondeterministic, run.status==Valid, and >=10 valid cases or an existing bug): groups spans by label, picks two same-label spans, and either duplicates the containing span's prefix (values[..start_b] + values[start_a..], the recursive-tree duplication) or replaces both with one donor's choice-value slice; probes through cached_test_function with a random-extension budget (BUFFER_SIZE - len) so diverged attempts complete instead of overrunning; up to SPAN_MUTATION_ATTEMPTS=5 per valid case, stopping at the first Interesting. This plus the engine's own kind-specific spans around every leaf draw (per project docs) is the existing 'copy data across a test case' machinery relevant to cross-timeline passes. Cross-VALUE duplication also exists in the shrinker: shrink_duplicates groups nodes by (kind discriminant, value) and shrinks whole groups in lockstep (integers.rs:353-418); lower_duplicated_characters lowers a shared codepoint across two strings simultaneously (strings.rs:323-371).

## Existing nondeterminism handling: the sticky engine flag
Engine.nondeterministic (test_runner.rs:988-998) flips when an executed case creates a state machine with max_concurrency > 1 (checked after execute via family.concurrent_machine(), test_runner.rs:1065-1070). While set: record_run skips tree recording entirely (so no simulate_full serving and no kind-mismatch check, test_runner.rs:1084-1096), targeting is skipped (425-437), span mutation skipped (439-445), the whole verify+shrink phase is skipped (gate at 473), DB persistence/reuse skipped (588, 1120-1122), and reproduce blobs are omitted from Failures (638-643) with TestRunResult.nondeterministic=true (650-653). So today's answer to nondeterminism is: turn off shrinking wholesale.

## Halt/error plumbing relevant to adding retry semantics
ShrinkHalt::{Stop, Error(RunError)} (mod.rs:98-114): Stop = deadline or improvement cap, absorbed by absorb_stop at shrink() exit keeping the best example (mod.rs:160-165, 694); Error propagates out of Shrinker::shrink as RunError for explore to surface (`shrinker.shrink().await?` at test_runner.rs:563 aborts the whole run). Adaptive searches (FindInteger, BinSearchDown/Big in search.rs) are probe/record value state machines whose convergence assumes each recorded verdict is stable — a flipped verdict mid-search silently converges to a wrong bound but doesn't error. The RNG for Probe continuations comes from Engine::rng_spawn (no per-probe seed; documented in ShrinkRun docs mod.rs:32-46).

RELEVANCE: The shrinker assumes the test outcome is a pure function of the choice sequence at four load-bearing layers. (1) Predicate evaluation is single-shot and centralized: one execution per candidate through Shrinker::run_test_fn -> EngineShrinkProbe -> Engine::cached_test_function, judged by exact (status==Interesting, origin==target_origin) match — a natural seam for an N-runs-with-quorum hook, but any such hook must also bypass or restructure the choice tree, because cached_test_function serves recorded paths from the tree without executing, freezing each path at its first observed outcome. (2) The tree's only nondeterminism detector is a choice-kind flip at a recorded position; outcome flips at the same path are silently overwritten, and during shrinking even the kind-mismatch diagnostic is discarded (test_runner.rs:1222) — only the pre-shrink verification replay surfaces NonDeterministic/Flaky errors, and both abort the entire run rather than degrade. (3) Acceptance and fixpoint logic assume verdict stability: consider's no-execute fast paths, sort-key-monotonic adoption of realized nodes, FindInteger/BinSearchDown convergence, fixate_shrink_passes' one-non-improving-step fixation for deterministic passes, and the stall guard all mis-converge (silently, not fatally) if a verdict can flip between probes. (4) Misalignment is already a first-class, well-handled phenomenon — punning, NodeGone, realized-node adoption, deficit-deletion repair, divergence-aware random-continuation probes — so the machinery for 'the test drew differently than proposed' exists and is reusable; what does not exist is any notion of 'the same sequence drew differently across runs'. The one existing stochastic pass (mutate_and_shrink, ShrinkPass::stochastic with a 6-failure retry budget) and the ShrinkRun::Probe random-continuation path are precedent for probabilistic pass semantics inside the fixpoint loop. Today's only nondeterminism strategy is the engine-level sticky flag from concurrent stateful testing, which disables the tree, shrinking, persistence, and reproduce blobs entirely.
