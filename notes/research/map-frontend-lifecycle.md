# Code map: frontend-lifecycle

> Research notes compiled 2026-09-02 at commit a0185a65 (branch base, == main at the time).
> References are `path:line` at that commit. Part of the nondeterminism design notes; see `../design.md`.

SUMMARY: The Rust frontend drives the engine via a pull loop in run_lifecycle::drive: hegel_next_test_case yields exploration-only (never final) cases, each wrapped in run_test_case which catch_unwinds the body, classifies the payload into TestCaseResult, and reports it via hegel_mark_complete; final replays are frontend-owned, replaying each reproduce blob after the loop drains. Nondeterminism already has one dedicated channel: the engine stamps cases via hegel_test_case_is_nondeterministic, the frontend then captures output+diagnostic+panic payload at discovery into a NondetStash, and a HEGEL_RUN_STATUS_FAILED_NONDETERMINISTIC verdict prints the stash and re-raises the stashed payload with no shrinking, replay, blob, or DB persistence. All other paths assume full determinism: a final blob replay that stops failing panics with a frontend FLAKY_DIAGNOSTIC, and engine-side Flaky/NonDeterministic RunErrors surface as HEGEL_RUN_STATUS_ERROR whose message the frontend panics verbatim.

## Pull loop shape
drive() builds SettingsHandle::build(settings, database_key), starts RunHandle::start (hegel_run_start with an output trampoline), then loops `while let Some(c_tc) = run.next_test_case()` calling run_test_case(c_tc, .., is_final=false). The engine only explores; every pumped case is non-final. After the loop drains, run.result() (hegel_run_result) gives the aggregate verdict and the frontend owns the final replays. Mode::SingleTestCase short-circuits to drive_single_case (one case, marked final, re-raised directly, no shrinking/replay).

## Panic -> TestCaseResult translation
run_test_case wraps the body in with_test_context(catch_unwind(AssertUnwindSafe(test_fn(tc)))). Payload classification: Ok->Valid; AssumeFailed->Invalid; StopTest->Overrun; LoopDone->Valid; InvalidArgument/InternalError are resume_unwound past the lifecycle (abort the run, never shrunk); any other panic becomes TestCaseResult::Interesting(Failure{origin: format!("Panic at {location}")}) using the panic hook's captured (thread, id, location, backtrace). report_outcome maps this to hegel_mark_complete(HEGEL_STATUS_VALID/INVALID/OVERRUN/INTERESTING, origin). Only status+origin cross the ABI; message and blob are recovered from the run result afterward. A libhegel non-OK draw rc is translated by raise_for_rc: HEGEL_E_STOP_TEST->StopTest, HEGEL_E_ASSUME->AssumeFailed, HEGEL_E_RETRY->LeafBudgetExceeded, HEGEL_E_INVALID_ARG->invalid_argument, HEGEL_E_ALREADY_COMPLETE->'moved to a thread that outlived the test' panic, else internal error (includes HEGEL_E_CONCURRENT_USE, considered unreachable in correct frontend use).
refs: src/run_lifecycle.rs:273-359, src/run_lifecycle.rs:369-383, src/backend.rs:19-40, src/test_case.rs:82-101, src/control.rs:1-47

## Panic hook and backtrace gating
init_panic_hook (Once) captures (thread_name, thread_id, file:line:col, backtrace) into thread-local LAST_PANIC_INFO only when currently_in_test_context(); control unwinds skip hooks entirely (raise_control uses resume_unwind). Backtrace capture is gated per case by CAPTURE_BACKTRACE, set to should_emit = ((is_final || capture_at_discovery) && !quiet) || verbose — discarded shrink probes never pay for backtraces. install_panic_info/backtrace_capture_enabled/set_backtrace_capture exist specifically so stateful::run_concurrent can ferry a worker thread's capture to the main thread; a panic on an un-ferried spawned thread falls back to unknown_panic_info -> origin "Panic at <unknown>", merging distinct threaded bugs into one counterexample (doc says fix deferred until structured concurrency support).
refs: src/run_lifecycle.rs:29-120, src/run_lifecycle.rs:200-217, src/run_lifecycle.rs:286-294, src/control.rs:102-133

## Final replay and re-raise (deterministic FAILED path)
On HEGEL_RUN_STATUS_FAILED, drive reads failure_count, prints the 'Property-based test failed with {count} distinct failures.' headline if >1, then for each index reads result.failure(index).reproduce_blob (hegel_internal_error if absent — every deterministic failure must carry a blob), rebuilds a standalone case via CTestCase::from_blob, and re-runs the user fn with is_final=true. If that replay is NOT Interesting it panics with FLAKY_DIAGNOSTIC. Otherwise it prints the diagnostic block, then reproducer_line (only when settings.print_blob && blob present: the '#[hegel::reproduce_failure("blob")]' text). Closing unwind: resume_unwind of the last replay's own panic payload for one bug, or a synthesized count-carrying panic for multiple.
refs: src/run_lifecycle.rs:599-644, src/run_lifecycle.rs:440-449, src/ffi.rs:375-400, src/ffi.rs:1434-1479

## Nondeterministic-run channel (already landed)
The engine stamps every case of a run it knows to be nondeterministic before the case starts; the frontend reads it once per case via CTestCase::is_nondeterministic() (hegel_test_case_is_nondeterministic; blob-replay handles are never stamped). run_test_case sets capture_at_discovery = !is_final && c_tc.is_nondeterministic(), which turns on emit (drawn values/notes recorded) and diagnostic rendering at discovery. drive buffers every non-quiet case's output lines into a per-case Arc<Mutex<Vec<String>>> sink and, on an Interesting result, overwrites a single NondetStash{lines, diagnostic, payload}. The stash is written unconditionally but read only on HEGEL_RUN_STATUS_FAILED_NONDETERMINISTIC: drive then prints stash lines + diagnostic and resume_unwinds the stashed payload — no final replay, no blob, no reproducer line. A frontend-interesting case can silently lose to an engine-side family conclusion (mark_complete after a conclusion is a no-op), which is why reporting is deferred to the run verdict; if the run passes the stash is discarded. The case that makes a run nondeterministic (first concurrent machine creation) is itself discarded engine-side, so every failable case was stamped up front.

## Settings surface
Settings fields: mode (TestRun/SingleTestCase), test_cases (default 100, HEGEL_TEST_CASES env override), stateful_step_count (default 50), verbosity (Quiet/Normal/Verbose/Debug), seed: Option<u64>, derandomize (default = in CI; fixed seed derived from test name), database (Unset/Disabled/Path; disabled in CI by default; HEGEL_DATABASE env override, 'disabled' keyword), suppress_health_check: Vec<HealthCheck>, phases: Vec<Phase> (Explicit/Reuse/Generate/Target/Shrink, all on by default), report_multiple_failures (default false), show_statistics (HEGEL_STATISTICS env), print_blob (default false, frontend-only, never forwarded over ABI), backend: Option<Backend> (None = auto). All others forwarded field-by-field in SettingsHandle::build via hegel_settings_set_* (phases and health checks as bitmasks). There is NO setting for flakiness tolerance, replay counts, or concurrency: stateful concurrency bounds arrive per-machine as min/max_concurrency args to hegel_new_state_machine, not via Settings. Determinism-touching settings today: seed, derandomize, backend, Phase::Shrink/Reuse, database.

## HealthCheck variants and triggers
Four variants (non_exhaustive): FilterTooMuch, TooSlow, TestCasesTooLarge, LargeInitialTestCase; HealthCheck::all() returns all four. Suppression crosses the ABI as a bitmask (hegel_settings_set_suppress_health_check). Triggers are engine-side in hegel-c/src/native/test_runner.rs, wrapped as RunError::HealthCheck with 'FailedHealthCheck: <Name> — ...' messages: FilterTooMuch on excessive invalid/overrun ratio during generation and on an exhausted search space where every reachable input was filtered; TooSlow when generation wall-clock exceeds budget; TestCasesTooLarge when inputs routinely exceed size budget; LargeInitialTestCase when the smallest natural input is oversized. All surface to the user through HEGEL_RUN_STATUS_ERROR -> result.error() -> panic!(message) in drive.

## Flaky/nondeterminism error message paths (user-visible today)
Four distinct paths: (1) frontend-detected flakiness — a final blob replay of a shrunk counterexample no longer classifies Interesting -> panic!(FLAKY_DIAGNOSTIC) ('Flaky test detected: Your test produced different outcomes when run with the same generated data...'); the same text exists engine-side as flaky_diagnostic() at hegel-c/src/native/test_runner.rs:762 for the engine's own pre-shrink verification replay (RunError::Flaky at test_runner.rs:544 when the verify replay's status or origin changed). (2) engine-detected generation nondeterminism — data-tree choice-kind mismatch message 'Your data generation is non-deterministic: at the same choice position with the same prefix, the choice kind changed from X to Y...' (data_tree.rs record_tree_full) -> RunError::NonDeterministic (test_runner.rs:539). Both (1-engine) and (2) become HegelRunResult::from_error -> HEGEL_RUN_STATUS_ERROR -> drive panics with the engine's message verbatim (no 'Property test failed' framing, no counterexample). (3) declared-nondeterministic run failing -> HEGEL_RUN_STATUS_FAILED_NONDETERMINISTIC -> stash-based report + resume_unwind; the engine also emits concurrent_machine_notice() ('Concurrent state machine detected: this run is nondeterministic, so failures are reported ... without shrinking, replay, database persistence, or a reproduce blob') once as an output line. (4) reproduce_failure blob that no longer fails -> panic 'reproduce_failure: the supplied failure blob no longer reproduces a failure. The failure may have been fixed, or the blob is stale.'

## Backend enum vs DataSource trait
Frontend Backend enum has two variants: Default (seeded PRNG, reproducible, shrinking/replay as usual) and Urandom (fresh /dev/urandom entropy per draw, for Antithesis whose fuzzer controls the device; Windows falls back to OS-seeded PRNG). Settings.backend: Option<Backend> maps to HEGEL_BACKEND_AUTO (None) / DEFAULT / URANDOM in map_backend; AUTO resolves engine-side (Settings::resolved_backend: urandom iff in Antithesis). This is NOT a pluggable data source: the DataSource trait (hegel-c/src/backend.rs:66-314) is engine-internal — the abstraction the C ABI drives, covering every typed draw, spans, collections, recursion, pools, state machines, targeting/events, clone_stream, is_nondeterministic(), and mark_complete — and its only implementation is the native engine (hegel-c/src/native/data_source.rs). The frontend cannot supply an alternative DataSource; it only selects the RNG. Urandom therefore makes fresh GENERATION non-reproducible from a seed, but choices are still recorded in the choice sequence, so blob replay, shrinking, and the final replay all replay recorded choices deterministically — the frontend has zero special-casing for Urandom ('The generation algorithm is otherwise unchanged — only the random source differs', runner.rs:100-101). The per-case nondeterminism stamp travels separately via DataSource::is_nondeterministic -> hegel_test_case_is_nondeterministic; the embed entry point hardcodes nondeterministic: false.

## Run-level result plumbing over the ABI
RunResult wraps hegel_run_result: status() (hegel_run_status_t: PASSED/FAILED/ERROR/FAILED_NONDETERMINISTIC), error() (hegel_run_result_error, Some iff run-level error), failure_count(), failure(index) -> ffi::Failure{reproduce_blob: Option<String>} via hegel_failure_reproduction_blob. HegelRunResult::status() engine-side: error.is_some() -> ERROR, failures empty -> PASSED, nondeterministic -> FAILED_NONDETERMINISTIC, else FAILED. TestRunResult (engine) carries failures + nondeterministic: bool; nondeterministic failures carry no blob by construction. Engine errors reach the frontend only as a rendered string (RunError::to_string at lib.rs:1310/1318) — the RunError variant (HealthCheck vs Flaky vs NonDeterministic vs UsageError vs Internal) is NOT distinguishable over the C ABI today; the frontend sees one opaque message and panics with it.
refs: src/ffi.rs:1406-1479, hegel-c/src/lib.rs:644-723, hegel-c/src/lib.rs:1305-1320, hegel-c/src/backend.rs:352-417

## TestCase threading/clone model and output capture
TestCase is Send + !Sync; clone() forks an independent libhegel handle (hegel_test_case_clone) onto its own choice stream, so clones on other threads draw concurrently without perturbing each other and replays stay deterministic per stream; the doc explicitly scopes the guarantee: 'Determinism extends exactly as far as your own code's determinism' — races on user state may not reproduce or shrink well. child() shares the same handle (Arc<CTestCase>) for composite bodies. Emission: TestCaseGlobalData.emit gates all draw/note recording; drawn values render into an engine-side family document (per-instance printer regions, assembled by anchor position so concurrent clones' output is deterministic); emit_rendered_output pushes the rendered document through the case's OutputSink after the body finishes. worker_line_prefix stamps '[worker N +X.XXXms]' on lines from concurrent stateful workers. All run output routes through RunOutput, resolved once at run start from the thread-local with_output_override sink (or stderr) so clones on other threads print to the right place.
refs: src/test_case.rs:196-299, src/test_case.rs:103-125, src/test_case.rs:362-411, src/test_case.rs:844-927, src/ffi.rs:357-429

## mark_complete concurrency contract
hegel_mark_complete is called once per case by report_outcome on the same shared handle the body drew on; the engine waits for any in-flight operation on the handle rather than erroring, so a still-running leaked thread cannot make the completion report fail; a TestCase that escapes to an unjoined thread keeps the handle alive via Arc and its later draws fail cleanly with HEGEL_E_ALREADY_COMPLETE. Draw primitives refuse concurrent use of a single handle (HEGEL_E_CONCURRENT_USE); Send/Sync for CTestCase is justified by libhegel's per-handle locks.
refs: src/run_lifecycle.rs:361-383, src/ffi.rs:361-367, src/ffi.rs:948-960, src/test_case.rs:72-100, src/test_case.rs:255-268

RELEVANCE: The frontend lifecycle is built around a hard determinism assumption with exactly one carved-out exception. The default path assumes: (a) a shrunk blob replayed via hegel_test_case_from_blob fails again with the same origin (else the run dies with FLAKY_DIAGNOSTIC, run_lifecycle.rs:622-624); (b) every FAILED-run failure carries a reproduce blob (hegel_internal_error otherwise, run_lifecycle.rs:615); (c) the failure report can be reconstructed entirely from a final replay, so nothing is captured during exploration (backtraces are deliberately not even captured for non-final cases); (d) bug identity is keyed on the panic's file:line:col origin, which assumes stable panic sites across replays. The exception — the concurrent-stateful nondeterminism channel — inverts all of that and is the template any extension would build on or generalize: an engine-owned per-case boolean (hegel_test_case_is_nondeterministic, read once at case start) flips the frontend into capture-at-discovery mode (buffer output lines per case, render the diagnostic at panic time, keep the caught payload in a NondetStash), and a distinct run status (FAILED_NONDETERMINISTIC) tells the frontend to report from the stash and skip replay/blob/DB entirely. Current limitations that constrain a design: the stash holds only the LAST interesting case (multiple distinct bugs collapse to one; report_multiple_failures is meaningless on this path); the stash can silently lose to an engine-side family conclusion and is discarded if the run passes; a run is all-or-nothing nondeterministic (flagged at machine creation, and the flagging case itself is discarded); engine RunError variants (Flaky vs NonDeterministic vs HealthCheck) are flattened to one opaque string over the ABI, so the frontend cannot react differently per cause; and Settings exposes no knobs at all for flakiness tolerance, verification-replay counts, or nondeterminism policy — the only related surfaces are suppress_health_check, phases (dropping Shrink), and the Backend RNG selector, which changes fresh entropy but never makes replay nondeterministic because replays feed recorded choices, not the RNG.
