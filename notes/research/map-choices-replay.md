# Code map: choices-replay

> Research notes compiled 2026-09-02 at commit a0185a65 (branch base, == main at the time).
> References are `path:line` at that commit. Part of the nondeterminism design notes; see `../design.md`.

SUMMARY: The engine records each test case as a Vec<ChoiceNode> where a node pairs a typed constraint with the drawn value (ChoiceData) plus a was_forced flag; clone streams (concurrent stateful) nest whole child sequences as one Clone-kind node. Replay feeds a Vec<ChoiceValue> prefix positionally through NativeTestCase::resolve_choice: an in-constraint value replays verbatim, a misfitting value is silently punned to the new kind's simplest()/unit() (never an error at draw time), drawing past the prefix either overruns (bare replay), resolves via a Simplest template, or extends from an RNG (probe). Determinism is enforced only after execution, by the data tree: a changed ChoiceKind at the same position aborts the run as RunError::NonDeterministic, and the lossless tree serves recorded conclusions for replayed paths without re-executing — so a flaky-but-kind-stable test is either caught by the pre-shrink verify / final blob replay (Flaky) or silently served stale results from the tree. A run-level `nondeterministic` flag (currently set only by concurrent state machines) turns all of this off wholesale: no tree recording, no novel prefixes, no shrinking, no DB persistence, no reproduce blob.

## Choice node representation
ChoiceNode { data: ChoiceData, was_forced: bool }. ChoiceData pairs constraint+value per kind: Integer(Arc<IntegerChoice>{min,max,shrink_towards:BigInt}, BigInt), Boolean(BooleanChoice{p}, bool), Float(FloatChoice{min,max,allow_nan,allow_infinity,smallest_nonzero_magnitude}, f64 — bit-exact eq), Bytes(BytesChoice{min_size,max_size}, Vec<u8>), String(StringChoice{intervals:Arc<IntervalSet>,min_size,max_size}, Vec<u32> codepoints), Clone(Arc<RealizedStream>). ChoiceKind is the constraint-only enum; ChoiceValue the value-only enum. Kind/value mismatch is unrepresentable inside ChoiceData; ChoiceKind::resolve is the single proving point.

## How draws append nodes
NativeTestCase (one *stream* of a family) owns prefix: Vec<ChoiceValue>, optional prefix_nodes, optional rng, nodes: Vec<ChoiceNode>, spans/span_events. Every typed draw (draw_integer/draw_float/draw_bytes/draw_string/weighted) calls resolve_choice then pushes a ChoiceNode; the draws layer wraps each draw in an engine-emitted span via draws::spanned(LABEL_INTEGER etc.). Spans: Span{start,end,label,depth,parent,discarded} plus live SpanEvent Open/Close tagged with draw position (needed to reproduce zero-width spans). FamilyCore is the cross-stream shared state: write-once conclusion, draw budget, target/event observations, fresh-id registry, GenerationParameters (swarm weights, drawn once per case, never recorded in the choice sequence).

## Clone streams (concurrent stateful)
NativeTestCase::clone_stream reserves one Clone-kind node in the parent and creates a child stream sharing the FamilyCore; on replay a ChoiceValue::Clone prefix at that index hands the child its recorded values (+realized nodes when available), any other value puns to an empty child. After the family concludes, reassemble() snapshots each child into RealizedStream{nodes,spans,span_events,flat_len} so the parent's nodes become the self-contained sequence. CloneRecord identity (Eq/Hash) is child values recursively — realized info never affects equality, so storage round-trips compare equal. Family conclusion is write-once (first stream wins); draws on any stream after conclusion fail fast with the family verdict.

## Replay: prefix resolution and misalignment punning
resolve_choice order: (0) pre_choice checks family conclusion and budget; (1) if nodes.len() < prefix.len(), from_prefix validates the recorded value against the CURRENT draw's kind+constraint — success replays it verbatim (was_forced=false); failure (wrong variant OR fails validate()) silently puns: if prefix_nodes are supplied and the stale value equals its ORIGINAL kind's simplest_value() → new kind's simplest(), else → new kind's unit() (second-simplest). Never an error, never clamped toward the recorded value. (2) past prefix: trailing_template (Simplest; count None=infinite, Some(0)→conclude EarlyStop+Overrun) — used by for_simplest and blob decoding punning; (3) RNG random sample; no RNG → internal error. for_choices caps max_size at choices.len() so a bare replay overruns on the first draw past the prefix (pre_choice concludes Status::EarlyStop and returns EngineError::Overrun → DataSourceError::StopTest, aborted latch). Stopping early is fine: trailing prefix values are simply never read; freeze() defaults status to Valid and closes open spans.

## Forced values
Forced draws bypass prefix AND rng entirely (pre_choice only) and record was_forced=true: weighted(p, forced) — also auto-forces p<=0/p>=1 without consuming a choice from prefix position; draw_integer_forced (UUID version nibbles, date/time internals); state-machine feature flags re-record decided flags as forced on later queries; collection force_stop. Consequences: the shrinker refuses to change a forced node's value (consider rejects same-length candidates that alter forced values); the data tree marks the position forced and treats it as having exactly one child (replay prefix value at a forced position is ignored, cursor still advances — simulate_full reproduces this).

## Data tree: what it records
DataTreeNode { kind: Option<ChoiceKind> (fixed on FIRST visit, includes full constraint — constraint drift IS kind drift since ChoiceKind eq compares constraints), forced, children: HashMap<ChoiceValueKey, Box<Node>> (floats keyed by to_bits, clones by recursive child-value CloneRecord), span_events, conclusion: Option<{status, origin, target_observations}> (recorded only for Status >= Invalid), is_exhausted (cached, propagated bottom-up via check_exhausted using max_children_saturating), clone_subtree (+ clone_subtree_disabled), stream_ended }. Engine::record_run feeds every executed case into record_tree_full — skipped entirely when the run is nondeterministic. The tree is lossless: any recorded path can be re-served (nodes, spans, status, origin, observations) without executing the body.

## Data tree: determinism assumption and its violation
Core assumption: at a given position reached by a given realized value path, the kind (constraint included) is always the same, and the same full path always yields the same conclusion. Violation of the kind assumption is detected in record_tree_full: a node whose stored kind != the run's kind returns the message 'Your data generation is non-deterministic: at the same choice position with the same prefix, the choice kind changed from X to Y…' which the runner converts to RunError::NonDeterministic (checked at 4 call sites: reuse replay, simplest probe, generation, shrink-verify; NOT checked for shrinker probes routed via cached_test_function, which discards the mismatch at test_runner.rs:1222). Violation of the value→outcome assumption is NOT detected by the tree — a recorded conclusion is served forever by simulate_full/cached_test_function, so a kind-stable flaky test silently gets stale cached outcomes during shrinking. Outcome flakiness IS caught at two dedicated replays: the pre-shrink verify (status/origin mismatch → RunError::Flaky with flaky_diagnostic()) and the frontend's final blob replay (panic!(FLAKY_DIAGNOSTIC) in run_lifecycle). Clone subtrees are the deliberate exception: contradictions inside a clone trie (kind change or stream-end change) return Err and merely disable prediction for that clone (clone_subtree_disabled) — cross-stream data dependence is legitimate there, not nondeterminism.

## Novel prefix generation and exhaustion
generate_novel_prefix walks the tree from the root: forced node → the single recorded child; Clone node → coin-flip between recursing into the clone_subtree (emitting ChoiceValue::Clone(CloneRecord::from_values(sub_prefix)) then stopping — clone child space is unbounded so it never exhausts) and descending a non-exhausted realized continuation; ordinary node → pick_non_exhausted_value (10 random samples from biased samplers avoiding exhausted children, then enumerate up to 1024). Exhaustion: node exhausted iff concluded, or kind known and children.len() >= max_children_saturating with all children exhausted (forced ⇒ 1 child suffices); kill_depths (discarded spans / kill_branch analog) exists in the API but production passes &[]. The walk fundamentally assumes prefix ⇒ deterministic continuation: the returned prefix is fed to for_probe expecting the body to re-request the same kinds. When the run is nondeterministic the engine skips prefixes entirely (empty prefix, pure random).

## simulate_full: tree-served replay
Predicts a for_choices replay without executing: reproduces forced-position skipping, misfit punning (same simplest()/unit() rule as resolve_choice, using prefix_nodes for the is-simplest check), and clone-position resolution (simulate_clone_stream walks candidate child values through the clone trie, reproducing punning inside the clone; disabled tries serve exact-value matches only). Returns Some(recorded conclusion) or Some(EarlyStop) as a *predicted overrun* when choices run out on recorded territory (valid only for extend==0 — cached_test_function executes instead when a random continuation budget exists), or None = previously-unseen behaviour → must execute. cached_test_function is the single replay chokepoint for shrinking and span mutation; there is no other result cache.

## Constraint checking / coercion on replay
choice_permitted logic = per-kind validate(): Integer range containment; Bytes/String length + alphabet membership; Float handles NaN via allow_nan, ±inf via allow_infinity gated on the relevant bound being unbounded, smallest_nonzero_magnitude band, and sign_aware_lte bounds (so -0.0/0.0 are ordered); Boolean accepts any bool unconditionally (BooleanChoice::eq compares p bit-exactly, so a changed p is a kind change but never a value rejection). There is NO clamping of replayed values — a failing value is replaced wholesale by simplest()/unit(). float_clamp (make_float_clamper port) exists only for fresh RNG float sampling. Two draws have bespoke repair-not-pun semantics: draw_fresh_id (replayed id out of window or already used → smallest unused) and draw_from_set (replayed non-member → largest member below it), both recording value-based integer nodes with registry-derived windows chosen so recorded kinds don't depend on realized values even across racing clone streams.

## Shrink ordering (sort key)
sort_key(nodes) = NodesSortKey: compare flattened_len (total choices counting clone children recursively) first, then top-level nodes.len(), then elementwise per-node keys — allocation-free lazy comparison. Per-node NodeSortKeyRef: cross-variant category Scalar(0) < Seq(1) < Clone(2); Integer → (|v − clamp(shrink_towards)|, v < target); Boolean → (v as int, false); Float → (float_to_index(|v|), is_negative), NaN = (u64::MAX,false); Bytes/String → shortlex with element keys (byte identity; codepoint's alphabet shrink-order rank: '0','1'..'9','A'..'Z', below-'0' reversed, above-'Z' natural); Clone → child flat_len, then len, then elementwise recursively. Shrinker::consider adopts a candidate only when the run is interesting with matching origin AND sort_key(actual_nodes) < sort_key(current) (actual realized nodes, post-punning — not the candidate); equal-key = already-target; forced values immutable. Engine keeps the per-origin minimum via update_interesting; DB ordering is byte shortlex over serialized choices; per-kind dense indices (to_index/from_index) enumerate values in exactly this shrink order for index-based passes.

## Existing nondeterministic mode (concurrent stateful)
Engine.nondeterministic is a sticky run-level flag. Mechanism: every test case of a not-yet-nondeterministic run has reject_concurrent_machine set; a state-machine creation with max_concurrency > 1 then fails as AssumeViolation (case discarded as Invalid) while FamilyCore::concurrent_machine records the request; after the execution, test_function flips Engine.nondeterministic and prints concurrent_machine_notice. All later cases get set_nondeterministic() stamped (exposed to the frontend via DataSource::is_nondeterministic) and rejection is lifted. While set: record_run skips the tree entirely (no kind check, no caching), generation uses empty prefixes, span mutation / targeting / verify+shrink are skipped (run stops generating at first bug via should_generate_more's shrink_enabled arg), DB persistence and reuse-alignment are off, failures carry reproduce_blob = None, and TestRunResult.nondeterministic = true → frontend status HEGEL_RUN_STATUS_FAILED_NONDETERMINISTIC, whose report comes from the NondetStash captured at discovery time (buffered output lines + diagnostic + panic payload) because there is no final replay.

## Run/replay entry points and constants
Exploration phases in Engine::run: reuse (DB replay via for_probe, RunError::NonDeterministic on mismatch, replay_aligned suppresses shrink), simplest probe (for_simplest), generation (novel prefix + for_probe_with_params / new_random_with_params), shrink (verify via for_choices with prefix_nodes → Flaky check → Shrinker with EngineShrinkProbe). Final blob replay lives in the frontend (run_lifecycle::drive) via hegel_test_case_from_blob → embed.rs decode_failure + NativeTestCase::for_choices(&choices, None, None). Constants: BUFFER_SIZE = 8192 choices per case; MAX_CLONE_DEPTH = 100; MAX_DEPTH = 1000 spans; MAX_SHRINKS = 500; MAX_SHRINKING_SECONDS = 300. Status enum: EarlyStop < Invalid < Valid < Interesting; conclusions are family-wide write-once.

RELEVANCE: The machinery is layered so that determinism assumptions live almost entirely OUTSIDE the draw path. Replay itself (resolve_choice) is already tolerant: any prefix value that no longer fits is punned to simplest()/unit() rather than erroring, overruns are ordinary EarlyStop conclusions, and clone streams already tolerate per-stream kind drift and cross-thread scheduling (clone nodes are keyed by realized child values; the family conclusion is write-once across racing streams; draw_fresh_id/draw_from_set were explicitly designed so recorded kinds don't depend on racing realized values). The determinism-dependent components are: (1) the data tree — kind-stability check (record_tree_full → RunError::NonDeterministic aborts the whole run), exhaustion accounting, novel-prefix generation, and the lossless conclusion cache that serves recorded outcomes without re-execution (this cache would actively mask outcome nondeterminism during shrinking); (2) the two flakiness replays (pre-shrink verify → RunError::Flaky; frontend final blob replay → FLAKY_DIAGNOSTIC panic), which assume a true counterexample reproduces on one replay; (3) the shrinker, whose consider() assumes replaying a candidate yields a stable interesting/not verdict and whose acceptance is gated on sort_key(actual) < sort_key(current) over realized nodes — any cross-timeline pass must produce candidates whose realized sequences strictly decrease under NodesSortKey (flattened_len, then len, then per-node keys) or the engine's per-origin minimum tracking (update_interesting) and DB shortlex ordering break; (4) DB reuse/persistence and reproduce blobs, which assume a choice sequence is a faithful reproducer. The existing concurrent-stateful escape hatch is all-or-nothing: one sticky Engine.nondeterministic flag disables every one of these at once, reporting the discovery-time failure unshrunk and blobless — so an extension handling nondeterministic tests gracefully would be carving capabilities back out of that blanket disable, and the clone-subtree design (predict when consistent, disable prediction on contradiction instead of erroring) is the one existing precedent for tolerating divergent re-execution inside the tree.
